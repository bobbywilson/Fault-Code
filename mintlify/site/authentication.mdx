---
title: "Authentication and permissions"
description: "Bearer request authentication and required permissions."
---

Every API request requires a Microsoft Entra access token issued for the dedicated Fault Code API. Send it in the request header:

```http
Authorization: Bearer <access-token>
```

The API validates the token signature, issuer, audience and expiry. Microsoft Graph tokens and ID tokens are not accepted. Never put tokens in URLs, logs or shared request examples.

## Required permissions

Each endpoint declares its required permissions. Delegated tokens require the declared scopes and an allowed user role. Application tokens require the declared application roles. Compound operations require every listed policy; resource ownership is checked separately. A valid token does not grant access to every record.

The endpoint reference lists `x-faultcode-required-policies` with the applicable scope and role requirements. For example, fault-code reads require `knowledge.read`; ontology writes require `knowledge.publish` with an allowed Engineer role or its corresponding application role.

## Authentication responses

| Result | Meaning |
| --- | --- |
| 401 | Missing, invalid, expired, wrong issuer or wrong audience token |
| 403 | Valid token lacks the required permissions |
| 404 | Resource absent or hidden by access filtering |

Documentation is public and requires no login. The separate [Swagger UI](https://faultcodeai.com/swagger/index.html) accepts a bearer token through **Authorize** when testing protected requests. Authorization is not persisted across reloads.
