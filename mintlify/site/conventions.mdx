title: "API conventions"

The API has six resources. Each supports the same five operations:

| Operation | Method | Path |
| --- | --- | --- |
| List | GET | `/api/v1/{resource}` |
| Get one | GET | `/api/v1/{resource}/{id}` |
| Create | POST | `/api/v1/{resource}` |
| Update | PUT | `/api/v1/{resource}/{id}` |
| Delete | DELETE | `/api/v1/{resource}/{id}` |

Replace `{resource}` with `incidents`, `vehicles`, `drivers`, `notifications`, `fault-codes`, or `ontology`. IDs are UUIDs. Every operation requires authorization. Users and roles are managed in Microsoft Entra, not through this API.

## Incident requests
Create an incident using `vehicleId` and `code`. The API finds the associated driver and creates a linked notification. The response identifies both records; it does not prove that email was sent. Check the notification's state and attempts for delivery results.

Update an incident with `status`. To resolve it, send `{"status":"Resolved","resolution":"Your investigation findings and recommended next step"}`. Resolution text is required, limited to 2,000 characters, and retained with its author, time, and version. Unknown fault codes can be resolved with recorded investigation findings; a catalog entry is not required. The update creates one follow-up notification. Check that notification for delivery results. Incident responses include `datadog` when a provider synchronization has been attempted: its `state` records the outcome and `url` identifies the accepted Datadog incident when present. A failed provider synchronization does not prove email failure. Investigation resolution does not mean that the vehicle has been repaired.

## Notification requests
Create a notification using `incidentId`; the API derives its driver and recipient. Duplicate active/source notifications return 409. Update `state` to `AwaitingAgent` to retry eligible processing, or `Cancelled` to cancel unsent work. Sent messages and receipts cannot be overwritten. Uncertain delivery cannot be blindly resent.

## Pagination and filters
Lists return `items`, `page`, `pageSize`, and `totalCount`. Pages start at 1; page size defaults to 20 and cannot exceed 100. Empty lists return `items: []`. Incident lists accept vehicle and status filters; notifications accept driver and incident filters. Use only parameters declared on the endpoint.

## Versions and retries
Read an individual resource's ETag and pass it as `If-Match` on conditional updates or deletes. Supply `Idempotency-Key` wherever the endpoint declares it. Retry the same payload with the same key after an ambiguous response. Changed payloads and stale versions return 409.

Deletes remove records from ordinary application views while preserving audit and delivery history. An active or uncertain send may prevent deletion with 409.

## Errors
Errors use `application/problem+json`, with `type`, `title`, `status`, `instance`, and `correlationId`. `X-Correlation-ID` identifies the request without exposing credentials.

| Status | Meaning |
| --- | --- |
| 400 | Invalid input or missing precondition |
| 401 | Missing or invalid authentication |
| 403 | Insufficient permission |
| 404 | Resource absent or outside authorized visibility |
| 409 | Version, state, duplicate, or replay conflict |
| 429 | Daily identity allowance of 200 API requests exhausted; retry after midnight UTC |
| 503 | Required service unavailable |
