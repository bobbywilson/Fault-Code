# Design

## Context
Part of FAU-14; see proposal.md. Qdrant1.19.2 is pinned by FAU-6; canonical persistence and model selection remain unresolved. Existing authorization uses knowledge.publish/read. No new Entra grants.

## Goals / Non-Goals
Deliver local provider-independent document lifecycle, HTTP adapters and disposable Qdrant acceptance. No generation, GraphRAG, arbitrary URL fetching, PDF parser, durable business provider or live paid calls. Ingest extracted bounded synthetic page text with explicit source/version; preserve that original verbatim.

## Decisions
- Domain immutable pages/content/revisions/publications; canonical store transaction contract serializes all tenant mutations and search against same authoritative state across processes. Test adapter only uses one-process semaphore/copy-on-write. Production unavailable503. Source IDs reserve deterministic tenant-scoped document GUIDs even after deletion; no reuse.
- Draft update requires strong aggregate version; publication increments version and snapshots approval/actor/time. Original publisher-only access is tied to publication actor, never supplied actor. Tenant access requires knowledge.read. Every document has one exact synthetic model/software pair and system; query matches all exactly. No arbitrary access grants or user-provided role arrays.
- Fixed chunk algorithm chars-v1: page-local consecutive500 UTF-16 units, no overlap, avoid splitting surrogate pairs; preserve text exactly. Pages1..20, each1..10000 units, total<=40000; source IDs SYN- ASCII tokens<=100, source versions<=40, titles<=200. Max100 documents per tenant, no binary/URL ingestion.
- Index collection suffix is SHA256(profile=model+dimensions+chars-v1), never silently reuse another model. Embedding config has no default model/dimensions; enabled mode requires explicit values. HTTP POST fixed OpenAI embeddings URL, float encoding, configured dimensions, exact returned model/count/index, finite nonzero vectors. No arbitrary configured OpenAI URL or redirects. Qdrant validates existing size/Cosine and never drops a mismatched collection.
- Versioned point IDs include tenant/document/publication/page/offset/checksum. Payload contains only tenant, revision key, system, model/software, approval, access, publisher and profile; canonical text is not trusted from vectors. Search constructs revision-key allowlist from authoritative approved access/applicability before query, filters tenant/approval/profile, then validates every hit's deterministic ID against regenerated canonical chunks. Scores>=0.75; limit1..20. No LLM answers or execution; evidence explicitly untrusted/unadjudicated; multiple results are not interpreted as a diagnosis.
- Publication marks index incomplete. Explicit document index or tenant reindex embeds/upserts approved chunks then atomically records profile readiness. Index exceptions roll back canonical marker; retry upserts same IDs. Search fails503 if eligible approval lacks index marker. Canonical tenant serialization covers search/index/publication; stale orphan points cannot enter allowed current revision keys. Reindex clears the tenant's points then rebuilds all current approved documents, including deleted cleanup; marks readiness incomplete before external effects, so failures remain503 until retried.
- Delete commits tombstone/replay/audit first, then purges document points; outage returns503 but tombstone remains hidden. Exact delete retry performs cleanup again. Idempotent index effects may survive canonical rollback as orphan points; allowlist/current chunk validation excludes them. This avoids claiming distributed transactions between canonical store and Qdrant. No durable dispatcher/outbox implied.

## Risks / Trade-offs
External calls under a tenant transaction can be slow: bounded data, timeouts and future adapter lock acceptance required. Character chunking is conservative and reproducible, not a tokenizer/relevance benchmark. Index readiness cannot detect out-of-band Qdrant data loss: operators must reindex after restore/loss; empty evidence never confirms unknown fault. DEC-001/003 adapter must preserve immutable history, retry retention, crash/multiple-process consistency and encrypted originals before activation. DEC-004 model choice remains separate; config pins an approved choice without choosing one here.

## Migration Plan
Additive APIs only; preserve baseline contracts. No package additions. Keep embedding disabled and canonical store unavailable by default. Disposable Linux CI uses real pinned Qdrant and deterministic mock embeddings, never production secrets. Production activation needs approved canonical provider, explicit model/dimensions, credentials and separately authorized live smoke. Rollback returns prior code; canonical adapter schema migration remains DEC-001.
