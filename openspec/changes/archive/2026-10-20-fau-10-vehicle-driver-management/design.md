# Design
Use immutable records and a tenant fleet snapshot transaction contract. The store MUST atomically serialize same-tenant writes, enforce expected versions, uniqueness, idempotency and audit together; future database adapter must provide equivalent constraints across processes. Read snapshots are tenant-scoped. Test storage lives only in tests, with a lock and copy-on-write rollback; production adapter always throws unavailable.

Vehicle identifiers are uppercase synthetic `SYN-` identifiers, drivers uppercase synthetic `DRV-` identifiers; owner mapping is a canonical nonzero Entra oid supplied only by an Operator or exact machine write grant. Owners are immutable after creation to prevent accidental reassignment. Minimal contact is an optional synthetic example.invalid email and email preference; no phone/address. No hard deletes or reactivation. Deactivation ends current associations at server UTC time, preserving past history. One active driver per vehicle; one driver may have many vehicles. Association replacement is explicit close then create. No backdating/future dating: server time only. Incident snapshots will retain IDs/history; no incident repository exists yet.

Writes use exact FAU-9 drivers.write/vehicles.write. Association writes require BOTH. Administrator is not a bypass. Reads use named all/own union entry policy with server-loaded resource authorization; vehicle owner derives from current association and driver mapping, never request fields. Unowned vehicles fail closed for reads. Staff writes can establish an initial association. Queries filter trusted tenant/owner before count/page. Read endpoints expose no owner oid. Cross-tenant and other-owner lookups return 404. Driver mapping changes require future separate audited design.

PUT/DELETE and association writes require a single strong quoted positive version If-Match; missing/malformed =>400, stale=>409. POST create and association require bounded Idempotency-Key, scoped to tenant+actor+client+operation and canonical payload hash. Same replay returns original result/version with no new audit; changed payload conflicts. Replay lookup precedes concurrency. Unit-of-work contains mutation, history, idempotency and safe actor/client/correlation audit. Cancellation passed throughout. Production 503 makes no durability claim.

No packages, provider schema or production in-memory fallback. Contract tests exercise real bearer middleware and production controllers with test-only storage. CI must run backend/containers on exact commit. Production acceptance for restart durability, multi-process concurrency, migrations and outbox remains blocked on DEC-001; do not mark that acceptance delivered.
