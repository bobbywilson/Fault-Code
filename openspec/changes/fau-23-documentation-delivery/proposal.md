# Proposal

## Why
Part of FAU-23. The completed feature tickets need a public Mintlify entry point and inspectable Linux release evidence without implying that pending durable storage or hosting exists.

## What Changes
- Add locked Mintlify tooling, public guides and exact generated OpenAPI synchronization with link/security/drift checks.
- Consolidate deterministic A/B/C and security evaluation evidence alongside existing Linux API, Angular and real Qdrant acceptance.
- Build SHA-versioned downloadable Linux images and exercise disposable image replacement/rollback with configuration and health checks.
- Document configuration, migrations, health, rollback, release criteria and pending external acceptance.

## Capabilities
### New Capabilities
None.
### Modified Capabilities
- `documentation-delivery`: public documentation verification, exact contract drift, Linux release manifests and honest rollback boundaries.

## Impact
Mintlify sources/tool lock, scripts, GitHub Actions and runbooks. No REST/MCP or model authority changes. ADR-007/008/009/010 apply. DEC-001 through DEC-005 remain unresolved; no host, database, paid tier, credential, tenant or external provider is selected. FAU-6/19/21/22 supply existing component acceptance; test doubles do not establish production durability.
