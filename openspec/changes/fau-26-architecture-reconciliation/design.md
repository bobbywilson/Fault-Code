### Driver notification browsing
The driver directory links to the selected driver's notification history. Driver Notifications is a paginated Spartan table of message, driver, email, delivery state, creation time and attempt count, with an all-driver view. GET /api/v1/notifications optionally filters by driverId and applies existing tenant, driver and incident visibility policies. Unavailable notification persistence must show an error rather than a fabricated empty inbox. Mailpit messages alone are not canonical notification records.

### Incident list presentation
Incidents is a read-only, paginated Spartan data table of vehicle-originated investigation records: fault code, vehicle, driver, system, reported time and status. Creation in Angular is available only by dispatching a fault from the Vehicles page. The table remains visible when persistence is unavailable, with the service error displayed and no fabricated records or empty-success claim.

### Vehicle fault dispatch and MCP email workflow (latest authoritative clarification)
The Vehicles action calls a dedicated dispatch endpoint with only vehicleId and code, plus an idempotency header. The server loads active driver association and seeded vehicle metadata; the browser cannot select a recipient, diagnosis, publication, occurrence identity or delivery status. Acceptance creates an incident and linked notification in the same durable transaction, before processing. Retrying an identical accepted request returns both original IDs.

The agent uses a fixed authorized MCP allowlist for exact approved fault lookup and email preparation/dispatch. This explicitly supersedes the old advisory-only/no-tools limitation for this bounded workflow; it does not grant arbitrary network, filesystem, recipient or knowledge-publication access. A lookup failure is not an unknown code. Known results produce evidence-grounded notification content; absent codes produce investigation-pending content and retain the incident. Explicit approved resolution queues another notification to the same driver; histories are append-only. Provider acceptance is distinct from delivery and from knowledge resolution/vehicle repair. Mailpit is the local/Linux capture target; Datadog is required telemetry. Missing persistence, provider or MCP capability must not simulate success.
