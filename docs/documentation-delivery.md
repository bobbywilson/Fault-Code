# Documentation and Linux delivery

Part of FAU-23; ADR-007/008/009/010. Public Mintlify sources live in `mintlify/site/` (tooling and tests stay outside that publishable root), with official `mint`4.2.1085 and Playwright1.64.1 locked by npm. No docs login or hosted deployment is configured. Do not install legacy `mintlify` CLI. Primary references checked October21,2026: https://www.mintlify.com/docs/cli/install , https://www.mintlify.com/docs/cli/commands , https://www.mintlify.com/docs/api-playground/overview and https://www.mintlify.com/docs/organize/settings .

## Generate and preview

Use Node22.22.3 and the pinned .NET SDK; run from checkout root:

```sh
dotnet restore FaultCode.slnx --locked-mode
dotnet build FaultCode.slnx -c Release --no-restore
python3 scripts/check-documentation.py artifacts/openapi/faultcode-v1.json --write
python3 scripts/check-documentation.py artifacts/openapi/faultcode-v1.json
python3 scripts/test-documentation.py
python3 scripts/test-release-evidence.py
cd mintlify
npm ci --no-audit --no-fund
npm run validate
npm run links
npx playwright install chromium
npx playwright test
npm run dev
```

Preview at http://localhost:5083. `--write` intentionally updates the committed exact generated OpenAPI; normal CI uses check-only. API compatibility remains checked against the committed baseline and PR base. The current generated contract has30protected operations across six resource groups. Official Mint validation and OpenAPI checks pass; `mint openapi-check` is deprecated in favor of `mint validate`. Swagger UI is installed for Development request testing. The three API guides and generated reference are readable in a clean anonymous browser context; desktop/mobile screenshot evidence comes from actual Chromium.

The public site contains API endpoints, authentication, and request/response conventions only. Operational pages were removed from the publishable root and preserved under `docs/archive/`. They are not part of the public API guide.

Mintlify uses `display:simple,proxy:false` and the exact generated OpenAPI with no configured server. It is reference documentation. Local interactive testing is provided separately by Swagger UI at `http://127.0.0.1:5080/swagger/index.html`, using the same generated `/openapi/v1.json`. Swagger UI is enabled only in Development, sends directly to the same API origin, does not persist bearer authorization, and changes no CORS policy or API authorization. This later user instruction supersedes the original no-Swagger UI decision for the local testing interface only.

## Tooling audit boundary

Official latest Mint CLI has upstream transitive audit findings (initial35:21high/9moderate/5low; compatible `npm audit fix` did not resolve them). CI retains the actual development-tool audit JSON, explicitly as a non-gating report; it is not a clean audit claim. CLI/parser/preview code runs only on trusted demo versioned docs in development/CI with read-only GitHub permissions and no provider credentials. It is absent from API/admin runtime images. Do not feed untrusted archives/media/MDX to this CLI or expose the preview as a hosted production service. Track vendor remediation before hosted/public service use. Frontend production dependency audit remains independently gating. No forced downgrade or untested transitive-major replacement is applied.

## Verification jobs and artifacts

- Backend foundation: strict specs, locked .NET build/all tests, actual TRX, generated REST/MCP validation, PR-base compatibility, format and extracted deterministic release evidence.
- Linux documentation: exact generated bytes, public/direct transport configuration, local navigation/link negatives, actual official Mint validation and7anonymous Chromium cases with screenshots; actual development-tool audit.
- Linux administration: component/service tests, mocked Entra/API UI, production Linux image/real401 boundary, fixture exclusion, rendered styles and frontend audit.
- Linux containers: isolated lifecycle/health/restart and authenticated disposable real Qdrant integration.
- Linux release candidate: SHA-tagged API/admin image archives, immutable labels/IDs/platform, SHA256SUMS, manifest and actual disposable rollback JSONL. Retention7days in private Actions storage; download/preserve intentionally before expiry.

No job publishes a registry image, deploys a host, enables live providers or closes Linear. Accept only all required passing checks on the reviewed head; missing/cancelled checks are not passing. Linux is authoritative; native local tests are supplemental.

## Deterministic release evaluations

```sh
dotnet test FaultCode.slnx -c Release --no-build --logger trx --results-directory artifacts/test-results
python3 scripts/release-evidence.py artifacts/test-results artifacts/release-evaluations.json
```

Use a fresh result directory. The extractor fails on non-passing results, absent expected methods/parameter counts and duplicate/stale selected evidence. It retains actual case names/durations/outcomes and source SHA, not fabricated metrics. Existing investigation fixtures require exact routing/provenance, support>=0.85 and no unsupported guidance; SDK tests assert strict schema, no tools and no implicit continuation. Signed demo JWT/permission/owner/MCP tests enforce authority outside the model. Negative fixtures cover missing definitions vs outage, injected/malformed output, concurrent replay, send/commit/lease failures and OTLP redaction. A/B real service chains reach a local acknowledged notification; C executes real investigation→engineering approval/publication→local notification in one service chain, with a separate approved-lookup case. These are test-only stores and local delivery, not a live durable deployment. Opt-in live-provider methods can return without a live call; their runner outcome is never treated as live-provider acceptance.

See [release runbook](release-runbook.md) for loading, promotion, rollback and outstanding decisions.
