# Operational telemetry

Part of FAU-20; ADR-006. Provider-independent Application contracts accept closed operation/outcome/error enums, elapsed milliseconds and nullable measured input/output token counts. Infrastructure SafeTelemetry owns nested standard ActivitySource scopes and sanitized records. LocalTelemetryAdapter projects records to Meter and structured ILogger; NoOpTelemetryAdapter emits nothing. Default `Telemetry:Provider=None`; set `Telemetry__Provider=Local` and restart for local diagnostics. Unknown/case-mismatched values fail startup without echoing supplied values. Exactly one adapter is registered; there is no implicit dual reporting.

`FaultCode.Operations` is the ActivitySource/Meter name. Operations are Api, Mcp, Incident (single incident reads), Retrieval (evidence search), Investigation and Model. Server-created API correlation propagates through application scopes; incoming X-Correlation-ID and traceparent cannot set the application trace root. Nested operations retain trace/parent/span IDs across async calls. External HTTP tracing remains framework-owned and separate. Logs record matching trace/span/server correlation. Model input remains curated; no telemetry context or execution capability is sent to it.

The contract has no arbitrary event name/property dictionary, raw Exception parameter, identity, resource ID, request path/query, driver contact, secret/token, prompt or document body. Invalid enum/usage records are suppressed. Counters are nullable and bounded 0..1,000,000,000; elapsed time is monotonic, clamped to 0..86,400,000 milliseconds. Metric labels are only operation/outcome (six by four values); IDs appear only in correlation records, never metric dimensions. Raw exception messages/stacks are never captured. Safe failure categories are Dependency, InvalidInput, Unexpected and Cancelled. Usage records only validated successful provider counters; failed-attempt billed usage remains unknown and reservations are never consumption. Replay does not emit another Model operation.

Collector exceptions and Activity listener sampling/stop failures are caught; business result, original error, cancellation and transaction commit/replay remain unchanged. No exporter retry, hidden worker, network client or queue exists. Adapter callbacks must be bounded in-process notifications: throwing code is isolated; malicious or blocking adapter code cannot be preempted. Operational records are best-effort and are not durable audit. Existing framework and authorization logs are separate and are not blanket-approved for export.

## Extension boundary

FAU-21 adds the approved Datadog/OpenTelemetry integration in Infrastructure/composition using these standard sources and sanitized records. Optional Sentry must implement the same adapter boundary; select it explicitly as the single reporting destination when implemented. Neither Datadog nor Sentry SDK/provider name is currently accepted by configuration. Do not enable automatic request/exception/identity/body capture or blanket logging exports. Do not weaken Compose's internal network. Account signup/trial walkthrough is separate from configured ingestion; credentials, terms, retention/costs and activation require their authorized steps. No remote telemetry, account, SDK exporter, hosting or paid commitment is delivered by this abstraction.

## Verification

TelemetryTests covers fake collector replacement, no-op/local selection, nested concurrent correlation, bounded/redacted records, partial usage, listener/collector outage, local trace/log/metric agreement and API 200/401 behavior. InvestigationTests executes real synthetic approved knowledge/rules/RAG/model orchestration with a throwing collector, verifies one committed investigation/audit and replay, and checks no identity/evidence/model-input leak. ApiHostTests verifies safe invalid-provider startup. ArchitectureTests retains exact package boundaries and checks vendor namespaces stay outside Domain/Application. Test stores remain one-process fixtures, not durable production storage.
